# IPTV backend

REST API на Go 1.26+ и PostgreSQL 17: каталог ТВ-каналов и HLS URL для просмотра.
Реализованы обязательная часть [ТЗ](docs/assignment.md) и подписки на отдельные
каналы: бессрочные и временные.

## Запуск

Нужны Docker с Compose и свободный порт `8080`. Команды выполняются из корня
проекта в Linux/WSL; Go на хосте для запуска не нужен.

```sh
docker compose --env-file .env.example up
```

После лога `HTTP server started` API доступен на `http://127.0.0.1:8080`.
Схема и demo-данные создаются автоматически: два пользователя и пять каналов.

| Логин | Пароль | Состояние |
| --- | --- | --- |
| `viewer` | `viewer_demo` | Активен |
| `inactive` | `inactive_demo` | Выключен, получает `401` |

`.env.example` содержит публичные настройки для локальной проверки.
Для своих настроек выполните `cp .env.example .env`, отредактируйте `.env`
и запускайте `docker compose up`.

Для пересборки добавьте `--build`, для остановки замените `up` на `stop`
или `down`. Данные сохраняются в volume `postgres_data`, в том числе после
`down`. Повторный запуск сохраняет изменения и удаления, не продлевает подписки.

## API

Оба ресурса требуют HTTP Basic Auth. Примеры выполняются во втором терминале.

```sh
curl -u viewer:viewer_demo http://127.0.0.1:8080/api/v1/channels
```

Ответ `200` на чистой БД в первые сутки после запуска:

```json
{"channels":[{"id":1,"number":1,"name":"Первый"},{"id":2,"number":2,"name":"Россия 1"}]}
```

Каталог содержит только активные каналы с действующей подпиской пользователя,
без URL потоков. Сортировка — по `number`, затем `id`; пустой список — `{"channels":[]}`.

```sh
curl -u viewer:viewer_demo http://127.0.0.1:8080/api/v1/channels/1/playback
```

Ответ `200`:

```json
{"channel_id":1,"url":"https://stream.example.com/live/ch1/index.m3u8"}
```

URL берётся из БД. Demo-ссылки показывают формат HLS-плейлиста, видеосервера нет.
ID — положительный десятичный `int64`; ведущие нули и `+` допустимы.
Оба ресурса поддерживают `HEAD`, который возвращает заголовки без тела.

Ответы API используют `Content-Type: application/json`, ошибки — единый формат:

```json
{"error":{"code":"unauthorized","message":"authentication required"}}
```

| Статус | `error.code` | Причина |
| --- | --- | --- |
| `400` | `invalid_id` | Неверный ID, ноль, отрицательное число или переполнение |
| `401` | `unauthorized` | Нет учётных данных, неверный пароль, неизвестный или выключенный пользователь |
| `403` | `subscription_required` | Активный канал без действующей подписки; URL не возвращается |
| `404` | `channel_not_found` | Канал не существует или выключен |
| `404` | `not_found` | Неизвестный путь |
| `405` | `method_not_allowed` | Неверный метод; `Allow: GET, HEAD` |
| `500` | `internal_error` | Внутренний сбой без SQL и других подробностей |

У `401` есть заголовок `WWW-Authenticate: Basic realm="iptv"`.
В `/api/v1` и `/api/v1/…` Auth проверяется до маршрута, метода, ID и
перенаправлений `ServeMux`. Лишний завершающий `/` даёт `404` после Auth.

## Подписки

Подписка связывает пользователя с каналом и хранит `active` и `expires_at`
(`timestamptz`). Для доступа пользователь, канал и подписка должны быть активны.
`NULL` в `expires_at` означает бессрочное право; временное действует, пока
`expires_at > statement_timestamp()`. Время берётся из PostgreSQL на начало
запроса; в сам момент истечения доступ уже закрыт, фоновая задача не нужна.

Выключение подписки запрещает доступ при любом сроке. Включение истёкшей
подписки без продления его не возвращает. Права проверяются при каждом запросе:
если срок истёк между каталогом и playback, последний вернёт `403`.

На чистой БД у `viewer`:

| ID канала | Подписка | В каталоге / playback |
| --- | --- | --- |
| `1` | Бессрочная | Да / `200` |
| `2` | На сутки с первого seed | До истечения: да / `200`; затем нет / `403` |
| `3` | Выключена | Нет / `403` |
| `4` | Уже истекла | Нет / `403` |
| `5` | Бессрочная, но канал выключен | Нет / `404` |

У активного пользователя без подписок каталог пуст, playback активного канала
возвращает `403`.

Управление — через SQL. Откройте psql (при работе с `.env` уберите `--env-file .env.example`):

```sh
docker compose --env-file .env.example exec db sh -c 'exec psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

Пример: выдать `viewer` бессрочную подписку на канал 3 или заменить существующую:

```sql
INSERT INTO subscriptions (user_id, channel_id, active, expires_at)
SELECT id, 3, true, NULL FROM users WHERE login = 'viewer'
ON CONFLICT (user_id, channel_id)
DO UPDATE SET active = true, expires_at = NULL;
```

Сделать её временной или продлить на час от текущего времени:

```sql
UPDATE subscriptions s
SET active = true, expires_at = statement_timestamp() + interval '1 hour'
FROM users u
WHERE s.user_id = u.id AND u.login = 'viewer' AND s.channel_id = 3;
```

В том же `UPDATE` используйте `SET active = false` / `SET active = true`
для ручного выключения/включения без изменения срока. Для бессрочного права —
`SET expires_at = NULL`, для истечения сейчас — `SET expires_at = statement_timestamp()`.
Точный срок можно задать как `timestamptz '2030-01-01T00:00:00Z'`.
`UPDATE 0` означает, что подходящей подписки нет. Изменения видны со следующего
запроса без перезапуска; для выхода из psql — Ctrl+D.

При обновлении версии без подписок используйте прежний Compose-проект,
настройки и volume с `up --build`. Миграции и seed применятся автоматически.
Права получат только сохранившиеся demo-записи `viewer` и каналов с исходными
номером и URL; существующие подписки не перезаписываются. Остальным пользователям
и каналам назначьте права вручную.

## Настройки

Compose читает `.env` или файл из `--env-file`; переменные окружения имеют приоритет.

| Переменная | Назначение / значение по умолчанию |
| --- | --- |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | Обязательные параметры БД в Compose |
| `DATABASE_URL` | Обязательный PostgreSQL DSN приложения |
| `HTTP_PORT` | Порт на хосте, `8080` |
| `HTTP_ADDR` | Адрес Go-процесса, `:8080`; в Compose задан явно |
| `DB_MAX_CONNS` | Максимум соединений pool, `10` |
| `LOG_LEVEL` | `debug`, `info`, `warn`, `error`; по умолчанию `info` |

В `DATABASE_URL` укажите те же пользователя, пароль и БД, что в `POSTGRES_*`;
внутри Compose адрес БД — `db:5432`. Спецсимволы в логине и пароле URL
нужно экранировать через percent-encoding. `POSTGRES_*` применяются только
к пустому volume: смена настроек не меняет пароль существующей БД.
При запуске через `make run` передайте переменные и доступный DSN через
окружение: само приложение `.env` не читает.

## Проверки

Для Makefile нужны Go 1.26+ и GNU Make:

```sh
make check
docker compose --env-file .env.example config --quiet
```

`make check` проверяет форматирование, build, vet и unit-тесты без Docker и БД.
Только unit-тесты — `make test` или `go test ./...`; остальные команды — `make help`.

Integration-тестам нужны Docker и свободный порт `15432`. Используется отдельная
PostgreSQL 17 в tmpfs; каждый тест создаёт и удаляет свою schema. Не указывайте
demo-БД в `TEST_DATABASE_URL`.

```sh
docker compose --env-file .env.example -f compose.test.yaml -p iptv-test up -d --wait db
(
  . ./.env.example
  export TEST_DATABASE_URL
  make integration
)
docker compose --env-file .env.example -f compose.test.yaml -p iptv-test down
```

Остановите test-стенд и при ошибке тестов. Параметры `TEST_POSTGRES_*`
и соответствующий `TEST_DATABASE_URL` приведены в `.env.example`.
Проверяются Auth, API и ошибки, миграции/seed, подписки и граница истечения,
отмена запросов и освобождение соединений. GitHub Actions запускает те же
`make check` и `make integration` для PR в `main` и push в `main`.

## Решения и ограничения

- PostgreSQL даёт транзакции для миграций и seed, но требует отдельного сервиса.
  `github.com/jackc/pgx/v5/pgxpool` — драйвер и pool; SQL написан явно,
  пользовательские данные передаются параметрами.
- `golang.org/x/crypto/bcrypt` нужен для хэширования паролей: в stdlib его нет.
  Cost — 10, соль случайная, пароли длиннее 72 байт отклоняются без усечения.
  Остальные внешние модули в `go.mod` — транзитивные зависимости pgx.
- HTTP, JSON, конфигурация, логи и тесты — на stdlib. `internal/httpapi` отвечает
  за HTTP, `internal/iptv` — за каталог и playback, `internal/postgres` — за SQL.
  Компоненты связываются в `cmd/server` через узкие интерфейсы у потребителей.
- Миграции встроены в бинарник, seed выполняется один раз. Каждый этап
  транзакционный, сбой останавливает запуск до открытия HTTP-порта.
  Это простая схема для одного экземпляра, без координации параллельного старта.
- Каждый авторизованный запрос обращается к БД и проверяет пароль через
  bcrypt. Без кэша изменения прав видны сразу, но высокая нагрузка не проверялась.
  Админ-панель, admin API и кэширование не реализованы.

Образ — статический бинарник в `scratch`, запуск без root. HTTP опубликован
только на loopback, порт БД не публикуется. На SIGTERM текущим запросам даётся
10 секунд, затем они отменяются и ресурсы закрываются; Compose ждёт 15 секунд.
Таймауты HTTP: headers — 5 с, read/write — 10 с, idle — 60 с; SQL — 3 с.
JSON-логи идут в stderr без секретов и текста SQL-ошибок: безопаснее, но
сложнее диагностировать сбои.

Basic Auth защищает выдачу URL; для внешнего доступа нужен HTTPS.
Сами HLS URL не подписываются, поток сервисом не защищён.

При дальнейшем развитии добавил бы защиту Auth от перебора и выравнивание
времени отказа, метрики и нагрузочные тесты. Для нескольких экземпляров
нужна координация миграций, для реального просмотра — видеосервер/CDN
с защитой доступа к потоку.
